# 問い合わせAPIの公開手順

Vercelのプロジェクト Firewall に、送信専用のレート制限を設定する。適用は公開承認後に行う。

| 項目 | 設定 |
|---|---|
| パス | 正規表現 `^/api/contact/?$` |
| HTTPメソッド | POST |
| 方式 | Fixed Window |
| 集計キー | Vercelが認識した送信元IP |
| 上限 | 300秒に8リクエスト |
| 超過時 | Default（HTTP 429） |

アプリ側ではIPや転送ヘッダーを取得・保存しない。設定はVercel Firewall側で管理し、アプリのデプロイだけでは有効にならない。

1. 既存ルール枠と料金条件を確認する。公開承認後に設定を反映する。
2. 事前検証には、合成入力を受け付けるモック送信環境を使う。同じIPから9回送信し、9回目が429になり、送信処理に届かないことを確認する。別パスとGETには影響しないことを確認する。
3. アプリを公開し、正規URLのフォーム表示を確認する。実メール送信は行わない。429と送信事業者エラーの集計を見て、共有回線で誤検知が続く場合のみ上限を再検討する。
4. アプリ側の不具合は前のデプロイへ戻す。制限値の問題はFirewall設定を個別に調整し、ダッシュボードの監査履歴から復元できるようにする。

同じ回線を使う利用者はIPの枠を共有する。固定窓の境界、IPが分散する送信、ハニーポットを避けるボットに対する抑止には限界がある。
