# CRM STEP 2-A

## 適用と切り戻し

本番適用は別途承認後に行う。対象プロジェクト、STEP 1の本人専用認可、復元確認済みバックアップ、既存の顧客・カルテ・サービス紐付け・担当先の件数と照合値を確認する。

1. `01-businesses.sql` を一つのトランザクションで適用する。既存サービスID・名称・事業割当が承認済みの対応表と矛盾する場合は停止する。
2. 新規2表のRLSと権限、8事業、既存行の照合値、未設定の顧客、追加された事業関係を確認する。
3. 画面を切り替える。旧版の `crm_create_customer` からのサービス紐付けにもDBトリガーが適用されるため、DBを先に適用できる。
4. 画面の切り戻しはSTEP 1版へ行う。事業の追加スキーマと入力済みの事業情報は保持する。承認なしに事業関係の削除や再分類を行わない。

事業のアーカイブは顧客全体のアーカイブから独立している。サービス追加は未確認の事業関係を作り、サービス解除は既存の事業関係を維持する。見込み客の入力UIはSTEP 2-Bで追加する。

## 合成データの検証

- `verify-local.sql` は外部ネットワーク無効の使い捨てPostgreSQLで実行する。Dockerイメージのエントリーポイントに `bash` を指定し、`supabase/rollouts` ディレクトリを `/crm-test` へ読み取り専用でマウントする。実行ファイルは `/crm-test/crm-step-2a/verify-local.sh`。
- ブラウザ検証はSTEP 1のローカルComposeを空の状態で起動し、リポジトリのルートから `node supabase/rollouts/crm-step-1/acceptance.cjs --seed --step2a --browser` を実行する。Supabase、画面、ゲートウェイはループバックを使用する。終了後は検証専用Composeプロジェクトを停止する。
