# CRM STEP 2-B

## 検証

- PostgreSQLの検証は外部ネットワーク無効の使い捨てコンテナで行う。`supabase/rollouts` を `/crm-test` に読み取り専用でマウントし、Bashで `/crm-test/crm-step-2b/verify-local.sh` を実行する。
- Auth、Data API、ブラウザの検証はSTEP 1の合成データ用Composeを空の状態で起動し、ルートから `node supabase/rollouts/crm-step-1/acceptance.cjs --seed --step2b --browser` を実行する。アプリはループバックを明示し、検証後に専用Compose環境を停止する。

## 本番適用と復旧

本番適用は別途承認後に行う。適用直前に、承認済み本人UUID、STEP 1のRLSと権限、CRMの件数・ID・照合値、復元検証済みバックアップを確認する。

1. `01-nus.sql` を一つのトランザクションで適用する。既存のNUS関係にサービス由来のデータがある場合は制約の追加が失敗するため、ロールバックして対象を調査する。移行処理で既存顧客の事業や区分を更新する処理は含めていない。
2. 既存CRMの認可と登録、新規テーブルとRPCの権限、既存データの照合値を確認する。安全性を確認してからアプリを切り替える。
3. アプリを戻す必要がある場合はSTEP 2-A対応版へ切り戻す。追加スキーマ、NUS情報、本人意思の履歴を保持する。

本人意思は顧客と範囲ごとに確認日時が最新の記録を採用する。同一範囲・同一確認日時の別記録は拒否し、同じ送信の再試行はリクエストIDで重複を防ぐ。「撤回」は該当範囲を未確認に戻す。全事業拒否が有効な場合は、NUSの個別許可より優先する。事務連絡の停止は「事務連絡を含むすべて」が明示されている場合のみ表示する。この段階では連絡送信、提案履歴、フォロー予定を扱わない。
