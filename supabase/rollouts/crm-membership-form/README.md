# 所属別フォームとCRM配色

従来の登録フォームはLillyの会員種別・サービスとNUS区分だけを表示していた。NUSの関心・看板出し・提案は個人カルテから編集する仕組みだった。共通編集フォームでは所属別フィールド自体が初回登録に限定されていた。今回、関心・看板出し・提案を共通フォームにも追加し、連絡意思と旧値の参照はカルテに残した。

共通フォームは既存値を読み込み、変更した専用項目だけを送信する。新RPCは既存のCRM認可と保存処理を使い、共通項目・所属・専用情報を同じトランザクションで保存する。テーブル変更や既存行の移行はない。

公開には別途承認が必要。適用前に既存データと権限を照合し、`01-save-details.sql` を先に適用する。新RPCの権限と既存の照合値を確認してからアプリを公開する。旧画面は既存RPCをそのまま使える。切り戻し時は入力済みデータを保持して画面を戻す。

隔離検証は空のSTEP 1用Composeで `node supabase/rollouts/crm-step-1/acceptance.cjs --seed --membership-a --common-name --browser` を使う。
