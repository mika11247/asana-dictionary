# NUS区分

通常の登録・編集・検索は単一区分（候補、愛用者、ダウンライン、アップライン、その他）と未設定を使う。「その他」には最大200文字の説明が必要。NUS所属を明示した場合だけ新規登録と同じトランザクションで保存する。既存顧客は「NUS情報を編集」から変更する。

旧の顧客区分と関係性は自動変換しない。旧「顧客」や「商品ユーザー／見込み客」から「愛用者」を判断できず、複数の関係性がある場合も優先順位を推測できないため、NUSカルテの「旧区分・関係性（参照のみ）」を見て本人が手動設定する。旧テーブルと履歴は保持する。関心・提案と区分は同じ保存で扱うが、連絡意思は従来どおり独立し、区分変更では書き換えない。

公開には別途承認が必要。既存顧客・所属・NUSの旧区分・関係性・連絡意思の照合値を保存せずに比較し、`01-category.sql` を先に適用する。追加表が空であることとRLS・RPC権限を確認してから画面を公開する。旧版は追加表を参照しない。切り戻し時は追加表と入力済み区分を保持し、旧画面でのNUS区分・関係性の編集を一時停止する。

隔離検証は既存のSTEP 1用Composeを空の状態で起動し、`node supabase/rollouts/crm-step-1/acceptance.cjs --seed --membership-a --common-name --browser` を実行する。
